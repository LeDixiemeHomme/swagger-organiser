Comment utiliser le service

À quoi sert Swagger Organiser ?

Swagger Organiser permet d'adapter un document Swagger/OpenAPI à un besoin précis. Vous pouvez réduire la documentation à certains endpoints, retirer des endpoints inutiles, découper un document volumineux en plusieurs fichiers ou reconstruire un document unique à partir d'une archive décomposée.

Le service accepte un fichier .json, .yaml ou .yml. Il produit une archive ZIP téléchargeable contenant le résultat de la transformation.

1. Keep endpoints — conserver une sélection

Cette action conserve uniquement les endpoints indiqués et supprime tous les autres du document.

Cas concret : votre Swagger décrit trois ressources : /users, /products et /orders, mais votre équipe ne doit publier que la ressource /users. Choisissez Keep endpoints et indiquez par exemple get:/users,post:/users. Le fichier généré ne contiendra plus que ces opérations.

2. Clear endpoints — supprimer une sélection

Cette action supprime uniquement les endpoints indiqués et conserve le reste du document.

Cas concret : votre Swagger contient les ressources /users, /products et /orders, mais l'ancienne ressource /orders ne doit plus être exposée. Choisissez Clear endpoints et indiquez get:/orders,post:/orders. Les ressources /users et /products resteront dans le document.

3. Decompose — découper un document

Cette action transforme un document OpenAPI unique en une archive ZIP contenant plusieurs fichiers : document principal, chemins et composants OpenAPI. Les catégories de composants sont conservées afin de permettre une reconstruction fiable.

Cas concret : votre Swagger contient plusieurs dizaines de ressources et devient difficile à maintenir dans un seul fichier. Utilisez Decompose pour séparer les chemins et les composants, puis versionner ou modifier ces fichiers indépendamment.

4. Merge — reconstruire un document

Cette action reconstitue un document OpenAPI unique à partir d'une archive ZIP produite par Decompose. L'archive doit respecter le formalisme de Swagger Organiser : cette action ne permet pas d'assembler arbitrairement plusieurs fichiers OpenAPI indépendants. Utilisez une archive générée par Swagger Organiser, ou une archive externe dont la structure et les références suivent exactement ce formalisme.

Cas concret : vous avez décomposé un Swagger avec Swagger Organiser afin de travailler séparément sur ses différents fichiers. Pour partager ensuite une version complète avec une autre équipe ou la présenter lors d'une revue d'API, utilisez Merge afin de reconstituer le document OpenAPI unique.

Déroulement d'une transformation

  1. Sélectionnez le fichier source, ou l'archive ZIP pour l'action Merge.
  2. Choisissez le format de sortie : JSON, YAML .yaml ou YAML .yml.
  3. Choisissez l'une des quatre actions. Pour Keep endpoints et Clear endpoints, saisissez les endpoints au format method:/path, séparés par des virgules.
  4. Lancez la transformation. Le fichier ZIP généré est téléchargé automatiquement.

Les erreurs de validation ou de traitement sont affichées sous le formulaire.

Le nom de l'archive est optionnel. Sans valeur, le service lit la valeur de info.title dans le Swagger fourni (par exemple DECISEO-API), puis conserve son nom par défaut si aucun titre n'est disponible. Le suffixe correspondant à l'action est ajouté automatiquement.
